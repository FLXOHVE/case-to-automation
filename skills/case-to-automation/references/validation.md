# 跨项目验证

本页是评审/验证方法。仅凭skill结构校验或下面场景的描述，不能声称已完成代理行为或业务实测。

可以在隔离项目副本用真实原生运行器检查以下情景；不接入未授权的业务环境：

| 输入情景 | 要观察的实际结果 |
| --- | --- |
| 两个不同语言/测试框架的项目，各有既有接口和用例 | 分别沿用项目组织与命令，不要求相同装饰器/Service；源用例与原生测试对应，真执行且有业务断言 |
| 项目已有基类/fixture、编号或注册规则，且同时留有过时或临时样例 | 依据当前模块和有效配置生成符合本项目的结构，通过适用静态检查及真实发现/注册；不把独立脚本当已集成用例 |
| 项目已有登录/连接、导航、读取、断言和清理，仅缺一个业务动作 | 原有能力被实际复用，只在既有职责层补动作；无复制驱动/页面、同义方法或无意义转发层，新增项有具体缺口依据 |
| 项目已有适配并规定保留电源/会话、禁入某认证页，而公共fixture或导航回退会触发这些动作 | 优先读取现有适配，核对完整生命周期；使用符合范围的局部路径或明确阻塞，不静默套用默认行为 |
| 已有通知接口或模拟回调，但真实退款权限、推荐/试驾/问卷来源事件尚缺条件 | 复用已有实现并分别标明事件来源和权限缺口；不伪造来源、不修改权限求通，也不把接口或夹具通过提升为真实整链路 |
| 框架无对应方法，但有版本匹配协议/界面/源码 | 补最小业务封装、读取与恢复，并验证；没有借用另一项目接口或写假成功实现 |
| 只有可操作界面，未提供页面路径和导航源码 | 从已知起点发现路径，记录错误分支与返回；补页面对象后从起点实际重放，保留路径和到达证据 |
| 同名菜单、隐藏模板、只读预览与可写开关并存 | 按父容器与角色限定唯一可见可写控件，不能盲取第一个或操作预览 |
| 保存时界面变On但重新进入后丢失，或正文通过而恢复失败 | 相应业务/清理断言报错，最终不通过；首败与复测保留 |
| 完全没有框架 | 根据该项目语言、构建和入口建立最小执行基础；关键选型缺依据时说明具体缺口 |
| 本次期望与旧缓存一致，动作实际未生效 | 独立结果判断失败，不能读取客户端预期变量冒充回读 |
| 视觉/音频等关键判据服务关闭 | 报告未完成相关判断，不把缺测当通过 |
| 正文成功但清理失败，或前置改变一半失败 | 原生结果和最终交付保留失败及恢复证据 |
| 原生命令退出0但没有测试，全部skip，选错测试或缺报告 | 自动核验拒绝标为通过 |
| 用例节点看似通过，但JUnit含套件级错误或未知/失败结果标记 | 最终拒绝通过，保留报告格式或初始化/清理错误的原因 |
| 分享材料引用本机文件、漏打包的图片或引用式链接 | 打包前报出具体缺失/不可移植引用，不交付表面成功但资源残缺的ZIP |
| 首次失败、修复后通过 | 保留两个运行及代码差异；未降低预期、未吞错或无限重试 |
| 只有skill和用例，没有源码/接口/目标环境 | 形成设计与最小缺口，不声称已生成可运行接口或已实机通过 |

辅助工具的隔离测试使用合成的JUnit文件验证状态判定；跨语言小样例应另用各自的真实测试运行器。
两者证明工具和约定能被执行，不代表任意新项目已经自动适配，更不代表所有设备/浏览器/APP已验收。

记录实际输入、源码与允许范围、生成代码、调用命令、结果和证据路径；分别报告结构检查、
辅助工具单测、样例原生执行、代理独立评估和目标业务环境实测。没有做的项留空或明确未做。
