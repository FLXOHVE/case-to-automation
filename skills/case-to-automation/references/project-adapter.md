# 项目适配与能力调查

用于第一次接触项目、缺少已有自动化说明或框架/版本变化时。不要求用户先编写适配文件。
先定位项目已有的工作流入口、适配说明和能力目录，沿该入口补充本次差异；同一项目不另建第二套同义适配。
首次调查只补尚未记录或已过期的相关信息，不能把“第一次使用本skill”理解为忽略项目已有积累。

## 调查顺序

1. 读适用的项目指令、README、依赖/构建/测试配置和CI测试步骤；先确定项目根、语言、版本和原生执行入口。
2. 找同模块/同测试类型、仍被当前入口或CI采用的代表性测试，核对当前规范后再参考；不照搬废弃或临时样例。
   沿动作、断言、fixture/生命周期和清理追到定义，检索相邻业务及公共层，查明可复用能力；读一个测试不能证明其正确。
3. 核对实际接口签名、返回值、异常、异步完成条件、超时及状态来源；记录是否有缓存、错误对象或旧响应风险。
4. 核对精确选择原生测试的方法、发现时的副作用、最终状态如何合并、失败与跳过如何报告。
   检查依赖/视觉/音频等服务关闭时是否会静默跳过断言，清理失败是否只是日志。
5. 在当前允许范围做小范围验证，再将可靠约定写入项目已有文档位置；标明仅查源码、离线通过或目标环境通过。
   后续读取时复核源码与版本，不能把草稿或示例命令提升为已验证。

没有已有测试框架时，先查项目技术栈、可测试入口及依赖约束，选择最小的适用测试方案并说明依据。
仅有用例而无项目源码/接口/界面或环境时，完成对应设计和具体缺口，不能保证生成可运行接口。
有可操作界面但没有导航定义时，按[页面调查流程](navigation-discovery.md)从当前页面建立实际路径，
再把已验证的入口、定位和到达判据登记为项目能力。不要把“缺封装”误判为“产品无该页面”。

## 缺失信息怎样处理

| 缺口 | 处理方式 |
| --- | --- |
| 页面路径、函数位置、格式或执行命令未提供 | 先查配置、有效测试、调用链及可访问界面，记录实际依据；不把可自行调查的工作推回用户 |
| 业务对象、验收判据、目标身份或授权范围经调查仍有歧义，或关键资料互相冲突 | 向用户提问并暂停依赖该答案的实现/操作；不任选一个对象、不编业务阈值或把猜测写成可执行动作 |
| 必要接口、协议、环境或观测能力无法获取 | 说明最小缺失项、受影响步骤及已完成范围，询问可提供的资料或访问方式；关键缺口未解决时保留待确认/未验证，不写成功占位 |

提问说明缺哪项、查过哪些材料、为什么影响实现或执行；有明确选项时给出选项及差异，避免只说“请补充信息”。
沿用已有回答和授权，不重复确认。等待期间推进独立且有依据的工作；没有回复不等于默认答案或批准。
对尚未确认的部分明确标注设计/待确认状态，不把它登记为已实现可运行或已通过。

## 生成前确认结构与复用

把本次模块实际适用的约定与来源记入适配说明，不另造统一模板：

| 核对面 | 要确认的项目约定及依据 |
| --- | --- |
| 目录与发现 | 测试所在目录、文件/类/函数命名、导入路径、注册清单及原生选择规则 |
| 声明与关联 | 用例ID/标签/装饰器/元数据、参数化及异步声明；手工用例与自动化的既有对应机制 |
| 生命周期 | 基类/fixture/钩子、作用域与注入、连接/账号准备、资源锁与清理错误传播 |
| 调用分层 | 已有页面对象、业务服务、驱动、断言、等待及恢复的职责和公共实现位置 |
| 配置与结果 | 目标和数据配置、超时/并发约束、日志/报告/附件，以及现有格式、类型和静态检查入口 |

保留配置与代表性测试的文件/符号依据。多种结构并存时沿本次模块及当前执行入口选择，
不要混搭不同代际写法；文档、样例和有效配置矛盾时调查真实入口，无法确定的具体冲突另列。
没有某类字段或机制的项目不强制补齐；也不能为了符合旧样例复制吞异常、漏断言等缺陷。

检索能力既看业务词，也看现有测试的调用链和公共层。调用前核对参数、前后置、作用域、
状态来源、异常及副作用，确认满足源用例语义，再决定直接复用、扩展已有能力或新增缺失能力。
复用已有登录/连接、导航、业务动作、读取、断言、等待和清理；只缺一个回读方法时不重写整套页面或驱动。
新增/扩展项记录未满足的具体契约及落层理由；避免复制代码、同义方法和没有新增语义的转发封装，
也不为本次用例做无关的全仓重构或提前搭建通用平台。

## 项目约束与业务事件来源

把已确认的项目规则和本次任务限制记在现有适配位置，并标明来源、适用模块和有效范围。
项目默认值不覆盖用户本次明确限制；历史任务的许可也不自动适用于新目标或新任务。

| 要确认的内容 | 实现前需要的依据 |
| --- | --- |
| 允许及禁止动作 | 例如保留电源/会话、禁入认证页面、禁止真实付款等；逐一检查setup、autouse fixture、导航回退、恢复和teardown是否间接触发 |
| 原生入口与必须复用的能力 | 当前登记/目录、客户端、驱动、页面、断言及资源锁的位置；本次新增项落在哪一层及不能直接复用的理由 |
| 事件来源 | 事件由哪个真实系统/入口产生、哪些字段由上游生成，以及当前使用真实来源、受控夹具还是模拟回调 |
| 身份与权限 | 操作主体、环境/站点、可操作对象范围、实际会话和授权依据；接口文档或本地开关不等于服务端已授予权限 |
| 关联与结果 | 来源记录/事件/订单等关联标识、业务状态转换、独立回读和未知写入的核对/恢复入口 |

约束与既有公共流程冲突时，不默默执行默认清理或绕过认证/业务入口；确认有符合范围的既有路径，
必要时在项目约定的局部作用域最小适配。没有可行路径则阻塞相应步骤并说明具体冲突，不全局修改其他套件。
业务事件或权限依据缺失时按前述缺口规则调查/提问，不能伪造来源记录或把夹具升级成真实整链路。

## 适配说明需要记录什么

按项目已有格式记录以下实际信息，不要求新建固定目录或填无关字段：

| 内容 | 记录要求 |
| --- | --- |
| 项目及版本 | 项目根、源码提交/构建或领域所需版本、调查时间；适用范围和实际执行版本分别列出 |
| 框架及组织 | 语言/框架、依赖入口、文件/类/函数约定、注册/发现规则、相邻可参考测试 |
| 执行入口 | 静态、离线和目标环境各自的精确命令/参数与工作目录，命令依据及已验证范围 |
| 选择规则 | 源用例ID怎样映射到原生测试ID，参数化/重复轮次怎样计数，是否依赖方法名或顺序 |
| 目标与依赖 | 配置项和资源占用机制、身份回读、账号/数据归属、网络/设备/辅助服务；不内嵌秘密和旧目标 |
| 生命周期 | 建立并确认起点、部分前置失败时恢复、正文与清理错误汇总、超时/中断后的恢复 |
| 结果 | 原生报告路径/格式、真实测试数量、跳过/零测试/缺报告判定、证据归属 |
| 关联 | 项目现有用例库或清单，自动化与用例/步骤的映射及部分覆盖表示方法 |

能力目录只整理当前任务所需部分，不先要求扫描整个仓库。每项至少记录：

| 能力 | 真实定义 | 契约 | 判据与恢复 | 可信范围 |
| --- | --- | --- | --- | --- |
| 对应本次具体动作/检查 | 文件和符号、参数签名、来源版本 | 前提、返回/异常、幂等性、异步完成条件 | 状态来源/有效性/新鲜度、恢复接口及失败行为 | 源码已核对、离线已验证、或某版本目标环境已通过 |

目录是检索入口，调用前仍核对相关实现。一个方法可能只发送请求，或在功能关闭时直接返回；
另一个可能返回False表示“无需改变”而非失败。既有代码和命名不替代契约检查。

## 不同项目如何适配

- Web：定位真实页面入口、控件和后端结果，明确异步保存、重载回读及测试数据清理。
- API：核对认证配置、请求/响应模型、业务状态、异步任务与资源归属；成功码不足以证明状态符合预期。
- APP：核对页面对象、系统权限、账号/连接条件、设备档案及页面返回/数据恢复。
- 设备：核对通道、身份、协议版本、响应有效性和新鲜度，区分信号状态与实际物理效果。
- 纯软件/库：优先现有测试框架和公开接口，核对进程内状态、文件/数据库等副作用及隔离恢复。

这些是调查方向，不代表已存在任何具体函数或可用环境。保留目标项目自己的调用和组织方式。
