# 没有导航定义时怎样找到页面

适用于用例只给页面名/功能名，项目没有对应导航或页面对象。调查导航和控件定位属于自动化实现工作。
优先复用当前项目和可用工具；不要要求所有项目暴露同一种页面树、路由或驱动。

## 1. 确认能观察什么

确认本次目标、版本、账号/角色和允许的操作，读取当前URL/场景、标题、面包屑、选中菜单、控件树或截图。
记录调查起点与进入前已有状态。缺浏览器/APP/设备操作工具时查可访问源码/路由/页面事件；
源码可给路径线索，受测用户入口仍需在界面确认。只有截图时可研究可见控件，不能把不可交互截图当作执行。
既无足够源码也无法观察/操作界面时，说明最小缺失项，不猜控件、坐标或隐藏接口。

为本次调查设定页面状态数、动作数或时间预算及停止条件，随项目规模调整并记录。
预算用于控制调查范围，不改变业务等待时间，也不作为反复失败后跳过用例的依据。

## 2. 从已知起点逐级探索

1. 提取页面和功能的业务词，结合当前菜单分组、上下文、搜索/滚动/更多入口选择有依据的候选。
   记录每个候选的来源；不把“通常在设置里”直接写成固定路径。
2. 每次只执行可解释的入口动作。动作后读取新页面身份和可见内容，验证实际转换，不能只记录点击返回成功。
   页面异步加载时按状态变化等待；不依赖固定sleep后默认到达。
3. 建立已访问状态记录：页面身份/父入口、动作目标、结果、是否找到线索及证据路径。
   错误分支按可见返回/关闭入口回退，再尝试尚未调查且有依据的分支，避免循环访问同一状态。
4. 调查阶段不为“试一下”随意切换业务开关、提交、删除或触发任务。需改变状态才能继续时，
   核对当前授权和前置，先登记恢复；信息不足的业务弹窗不统一Cancel/确认来强行清路。

浏览器优先当前页面的语义/可访问性树和可见DOM；APP/设备使用当前可用的UI树或截图能力。
动态产生的DOM标识、会话路由、历史坐标只作当次线索；调查记录和脚本中区分稳定定位与一次性证据。

## 3. 排除“同名但不是目标”

按当前页面及父容器限定目标，结合角色、可访问名称、关联标签、控件ID和布局确认归属。
对可操作目标检查唯一、可见、启用、无遮挡且在有效视口；需要时滚动后重新读取树/坐标。
页面里有多个General或同名开关时，先区分菜单分组、真实表单、只读预览和隐藏模板。
不得为消除多匹配直接取第一个节点；只有定位范围和证据证明唯一后才操作。
仅找到label不等于找到开关；点击后应从真实交互控件/独立业务状态读取结果。

## 4. 确认到达并补封装

到达判据应同时包含页面身份和该页特有内容/目标控件，不能只看URL、标题中的一个通用词或截图存在。
需要证明用户入口时记录起点、每步真实点击与到达证据；RPC直跳/后台状态修改只用于明确的准备。

将实际发现结果写入项目适配或页面对象，至少包含：

- 适用版本/布局、起点及前提；实际入口链和每步到达判据。
- 目标控件的角色/标识、父级范围、可见/启用及唯一性检查；定位依据和原始证据。
- 返回/离开方式、可观测初始状态、恢复目标和部分失败时的处理。
- 调查与封装状态：仅发现、已重放验证或当前版本已通过，避免把未跑路径当作可用能力。

沿项目分层补导航、控件读取/设置、等待和断言；测试用例只编排业务步骤。
从已知起点重放封装验证，不能因为探索时已经站在目标页就省略入口验证。

## 5. 前置、恢复和验收

保留源用例的业务起点、顺序及预期。项目接口要求的连接/登录/页面就绪作为技术前置另列，
不把临时准备状态写成产品默认值。首次变更前读取并保存本次原值、数据归属及必要的起始页面/会话信息。
恢复由本次变化与源用例约定决定，必须早于副作用登记；前置改变一半、正文失败也尝试本次恢复。
正文结果与恢复失败分别保留，关键恢复未完成不能算通过；恢复到原On时不能统一写成Off。

小范围验证覆盖：从已知起点实际进入、正确的同名控件、操作后状态、离开再进的持久状态及恢复后状态。
有必要时验证相反初态和中途失败；正常路径通过后只针对新变化和未决风险补测。
在隔离副本可以注入保存不生效或恢复失败，确认断言及最终结果会拒绝通过；不在业务环境人为制造这些故障。

遇到无新线索的循环、达到调查预算、定位仍有歧义、页面无到达证据、目标离线/版本不符、
或下一动作超出当前范围时停止相应分支，留下访问路径、当前状态、证据和最小后续条件。
找不到页面先核对版本、角色、功能启用和前置，不凭一次搜索就认定产品无功能，也不编造路径继续跑。
