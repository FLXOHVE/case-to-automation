# Case to Automation：用例转自动化与执行核验

输入**已有测试用例 + 目标项目**，让编码代理调查项目能力、生成符合原框架的自动化，并保留可核对的执行证据。

这是 **Agent Skill + 执行核验工具**，不是独立大模型应用，也不是已经支持任意项目的一键生成器。需求分析和用例设计由上游 AI 用例工作台负责；这里从已有用例开始。

## 无账号、无设备试玩

Python 3.10+，在仓库根目录执行：

```sh
python tools/demo.py --output demo-output
python -m unittest discover -s tests -v
```

演示会针对虚构任务清单运行真正的 `unittest` 断言，分别检查通过、故意注入缺陷、跳过测试、零测试四种结果。每种运行都有 JUnit、日志、源码哈希和 `verification.json`。

演示总命令成功表示四种情况都被正确识别；其中故意失败的场景仍然是失败。示例自动化代码已经提供，不宣称本次演示由 AI 动态生成，也不宣称完成真实产品验收。

可以先阅读[源用例](examples/task_list/cases.md)，再看 `examples/task_list/run_tests.py` 中对应的断言。

## 使用与边界

- 将 `skills/case-to-automation/` 整个目录安装到你的编码代理支持的技能位置，再提供项目路径、用例和允许执行的范围。
- 技能要求复用目标项目的目录、fixture、页面对象、业务服务和断言；缺能力时先调查依据。
- 可选核验脚本检查实际选中测试、数量、错误、跳过、进程退出码、报告新鲜度及源码变化。
- 核验脚本会执行用户提供的命令，不是沙箱；它不能替代业务断言评审，也不能保证终止全部子进程或恢复外部业务状态。
- 当前附带样例只证明离线工具和真实测试运行器能够工作；其他语言、设备或应用的代理转换效果需要另行评测。

独立打包技能：

```sh
python skills/case-to-automation/scripts/package_skill.py --output dist/case-to-automation.zip
```

每次使用新输出目录，保留首败与复测。安装包只包含技能本身，演示与仓库测试不包含其中。
