# Case to Automation

**Turn reviewed test cases into project-native automation, with execution evidence.**

[中文说明](README.zh-CN.md) · [Agent skill](skills/case-to-automation/SKILL.md) · [Synthetic input cases](examples/task_list/cases.md)

This repository contains an agent skill and optional Python tools for verifying native JUnit results. The skill guides an existing coding agent to investigate a target project, reuse its test architecture, implement missing capabilities, and preserve evidence. It is not a standalone LLM application or a universal test generator.

The input is an existing test case plus a target project. Requirements analysis and test-case design belong to a separate upstream workbench.

## Run the offline demonstration

Python 3.10+, no third-party dependencies, from the repository root:

```sh
python tools/demo.py --output demo-output
python -m unittest discover -s tests -v
```

The demo runs real `unittest` assertions against a tiny, fictional task-list implementation. It demonstrates four outcomes:

- Passing assertions are accepted.
- An intentionally injected archive bug produces a rejected failure.
- A skipped test is rejected as incomplete.
- Zero selected tests are rejected even though the native runner exits successfully.

Each scenario writes a fresh JUnit report, process log, source hashes, and `verification.json`. The demo command exits successfully only when all four scenarios receive their expected verification verdict. **That demo success does not mean the intentional failing scenario passed.**

The example automation is supplied source code, not code newly generated by an AI during the demo. It proves the evidence helper works with a real test runner. General agent behavior across arbitrary applications still requires separate evaluation.

## Use the skill

Copy `skills/case-to-automation/` into your coding agent's supported skill directory. Provide the target repository, existing test cases and authorized execution scope. The skill itself does not supply a model, accounts, drivers, or access to business systems.

The optional verifier runs an explicitly supplied native test command and checks selected test IDs, counts, failures, skips, exit code, report freshness, and selected source changes. It is not a sandbox and does not prove that business assertions are sufficient. Child-process cleanup and external effects remain the target project's responsibility.

Package only the portable skill:

```sh
python skills/case-to-automation/scripts/package_skill.py --output dist/case-to-automation.zip
```

Use new output paths; existing evidence and archives are not overwritten. `dist/` contains the installable skill; the offline demo and repository tests remain in this repository.
